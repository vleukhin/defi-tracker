# ТЗ. Часть 2: Фаза 1 (MVP) — «Трекер аллокации с чтением кошельков»

**Версия:** 1.0 (30.07.2026)
Документ самодостаточен: разработчик может реализовать Фазу 1, не читая остальные части (архитектурные детали — в [04-arhitektura.md](04-arhitektura.md)).

---

## 1. Цель фазы

Пользователь регистрируется, добавляет свои EVM-адреса, приложение читает балансы на Ethereum / Arbitrum / Base / Optimism, оценивает их в USD и показывает текущую аллокацию против заданной целевой — с отклонениями и суммами к покупке/продаже.

**В MVP нет:** DeFi-позиций (Aave/GMX/LP), сделок и средней цены, снепшотов, истории, экспорта.

## 2. Состав MVP

1. Регистрация и вход, изоляция данных.
2. Управление кошельками (read-only адреса).
3. Чтение балансов: нативные монеты + ERC-20 на 4 сетях.
4. Цены из CoinGecko через общий серверный кэш.
5. Корзины активов и целевые пропорции.
6. Дашборд: стоимость портфеля, аллокация, отклонения.

## 3. User stories и критерии приемки

### S1.1. Регистрация и вход
*Как пользователь, я регистрируюсь и вхожу, чтобы мой портфель был приватным.*

- [ ] Регистрация по email + паролю с верификацией email; пароли хэшируются argon2id (или средствами Supabase Auth).
- [ ] Сброс пароля по ссылке на email.
- [ ] Rate-limit на попытки входа; сессии HttpOnly + SameSite; только HTTPS.
- [ ] Ни один пользователь не может получить данные другого ни через один API-роут — покрыто автотестом (RLS-политики, см. Часть 4 §5).

### S1.2. Управление кошельками
*Как пользователь, я добавляю один или несколько EVM-адресов (read-only), чтобы балансы появлялись автоматически.*

- [ ] Добавление адреса: валидация формата и EIP-55 checksum; опциональная метка («Основной», «Ledger»).
- [ ] Один адрес автоматически отслеживается на всех 4 сетях; отключение отдельных сетей не требуется в MVP.
- [ ] Удаление кошелька убирает его балансы из портфеля.
- [ ] **Нигде в UI нет полей, упоминаний или запросов приватных ключей и сид-фраз.** Явный текст при добавлении: «Только просмотр. Приложение не может распоряжаться средствами».
- [ ] Резолвинг ENS-имен — nice-to-have, не обязателен.

### S1.3. Чтение балансов
*Как пользователь, я вижу свои нативные и ERC-20 балансы на Ethereum, Arbitrum, Base и Optimism.*

- [ ] Балансы читаются напрямую из блокчейна: нативная монета + ERC-20 `balanceOf` батчем через Multicall3 по курируемому списку токенов (см. Часть 4 §6.1); discovery неизвестных токенов — ежедневный свип через Zerion API (free tier).
- [ ] Обновление: по кнопке «Обновить» (debounce 60 с на кошелек) и автоматически не чаще раза в 15 минут при открытом дашборде.
- [ ] Отказ RPC одной сети деградирует только эту сеть: показываются последние известные балансы с бейджем «данные устарели: {время}»; дашборд не пустеет.
- [ ] Decimals берутся из контракта токена, никогда не предполагаются равными 18. Сырые значения хранятся как bigint + decimals.
- [ ] USDC и USDC.e (bridged) — разные активы, не объединяются автоматически.

### S1.4. Цены
*Как пользователь, я вижу стоимость каждого актива и всего портфеля в USD.*

- [ ] Цены по адресу контракта через CoinGecko `/simple/token_price/{platform}` (+ `/simple/price` для нативных монет); только с сервера, через общий кэш с TTL 5 минут.
- [ ] На дашборде видна метка «цены обновлены {N} мин назад»; цены не старше 5 минут при активном обновлении.
- [ ] Токены без цены в CoinGecko попадают в секцию «Нераспознанные», по умолчанию исключаются из итогов и аллокации.
- [ ] Спам/пыль: токены без листинга CoinGecko или стоимостью < $1 скрыты по умолчанию, есть переключатель «показать скрытые». Цена неизвестных токенов никогда не подтягивается автоматически (защита от скам-токенов с фейковой ценой).
- [ ] Атрибуция «Price data by CoinGecko» со ссылкой — в футере.

### S1.5. Агрегация активов
*Как пользователь, я вижу один актив одной строкой, независимо от сети и кошелька.*

- [ ] ETH на 3 сетях + WETH в 2 кошельках сворачиваются в одну строку «ETH» с раскрываемой разбивкой по источникам (кошелек × сеть).
- [ ] Правила отождествления по умолчанию (переопределяемые на уровне корзин, см. S1.6): WETH → ETH; один и тот же токен на разных сетях — один актив.

### S1.6. Корзины и целевые пропорции
*Как пользователь, я задаю целевые проценты по корзинам активов, чтобы измерять отклонение.*

Цели задаются на **корзины** (классы активов), а не на отдельные токены: никто не держит цель «40% WBTC-на-Arbitrum» — цель звучит как «40% экспозиции в BTC».

- [ ] Встроенный маппинг актив → корзина (переопределяемый пользователем): WBTC, tBTC → **BTC**; WETH, wstETH, stETH, rETH → **ETH**; USDC, USDC.e, USDT, DAI, USDe → **Stablecoins**.
- [ ] Пользователь может создавать свои корзины (например, «L2-альты» = ARB + OP) и переносить любой актив в любую корзину.
- [ ] Активы без корзины попадают в **«Прочее»** — отображается, целевого процента не имеет (опционально можно задать).
- [ ] Редактор целей: процент на корзину; валидация предупреждает (не блокирует), если сумма ≠ 100%.

### S1.7. Дашборд аллокации
*Как пользователь, я вижу текущую аллокацию против целевой с отклонениями.*

- [ ] Шапка: общая стоимость портфеля (USD), метка свежести цен и балансов.
- [ ] Таблица по корзинам: текущая стоимость $, текущий %, целевой %, отклонение в процентных пунктах, сумма ребалансировки в $ («Купить $980 BTC» / «Продать $1 240 ETH»).
- [ ] Донат-чарт текущей аллокации.
- [ ] Отклонения за пределами ±5 п.п. (порог по умолчанию) визуально выделены; сводка одной строкой: «Максимальное отклонение: BTC +7.2 п.п. ($3 400 сверх цели)».
- [ ] Формулы: `отклонение (п.п.) = текущий % − целевой %`; `сумма ребалансировки = целевой % × стоимость портфеля − текущая стоимость корзины`.
- [ ] Строки корзин раскрываются в состав (активы → источники).
- [ ] Дашборд загружается < 2 с на кэшированных данных на телефоне среднего класса; полностью удобен на экране 375 px.

## 4. Out of scope Фазы 1 (явно)

- DeFi-позиции: aToken, GM-токены, LP-NFT читаются как обычные ERC-20 и попадают в «Нераспознанные» (не в итоги). Полноценная поддержка — Фазы 4–5.
- Сделки, средняя цена, P/L — Фаза 2. Ручные позиции (CEX/холодные кошельки) — Фаза 2.
- Снепшоты и история — Фаза 3.
- CSV-экспорт, метки/фильтры по кошелькам, алерты, 2FA — Фаза 6.
- Разбор истории транзакций, подпись транзакций, не-EVM сети, NFT, валюты кроме USD — постоянные non-goals.

## 5. Определение готовности фазы

- Все критерии приемки S1.1–S1.7 выполнены.
- Автотест изоляции данных проходит (два пользователя не видят данных друг друга).
- Реальный портфель (3 кошелька × 4 сети, ~15 активов) корректно агрегируется и совпадает с DeBank/Zerion по составу токенов (±спам).
- Расход API за неделю тестирования ≤ 25% лимитов бесплатных тарифов.
- Путь «регистрация → адреса → отклонения» проходится новым пользователем за ≤ 10 минут.
