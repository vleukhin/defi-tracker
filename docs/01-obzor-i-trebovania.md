# ТЗ. Часть 1: Обзор продукта и общие требования

**Продукт:** легковесный веб-трекер DeFi-портфеля
**Версия документа:** 1.0 (30.07.2026)
**Статус:** утверждено к разработке

---

## 1. Назначение продукта

Облачное мультипользовательское веб-приложение для учета криптовалютного портфеля:

- автоматическое чтение балансов и DeFi-позиций по адресам кошельков (read-only);
- целевые пропорции портфеля и отклонения от них с рекомендациями по ребалансировке;
- ручной леджер сделок с расчетом средней цены покупки и P/L;
- снепшоты портфеля и графики истории;
- учет средств в лендинге (Aave v3: supplied/borrowed, health factor);
- учет размещения заемных средств (GMX v2 GM-пулы, Uniswap v3 LP) с ручной привязкой «займ → позиция».

Продукт — инструмент для энтузиастов («я + друзья», < 20 пользователей), не коммерческий сервис. Приоритеты: легковесность, скорость ежедневной проверки портфеля, нулевая/минимальная стоимость инфраструктуры.

## 2. Утвержденные решения и ограничения

| Решение | Значение |
|---|---|
| Источник данных о позициях | Чтение по адресу кошелька (read-only). Приватные ключи — никогда |
| Сети | Ethereum, Arbitrum, Base, Optimism (EVM) |
| Сделки для средней цены | Только ручной ввод (разбор истории транзакций — постоянный non-goal) |
| Учет долга в аллокации | **Гросс-подход**: проценты считаются от суммы всех активов; долг — отдельной строкой. Net worth = активы − долг в шапке |
| DeFi-протоколы | Только Aave v3, GMX v2 (GM-пулы), Uniswap v3. Остальное — «нераспознанные позиции» |
| Цены | CoinGecko (Demo-тир, 10 000 вызовов/мес), общий серверный кэш |
| Валюта отображения | Только USD |
| Пользователи | Мультипользовательский: регистрация, строгая изоляция данных |
| Бюджет внешних API | ≤ $50/мес. Целевая конфигурация — $0/мес (см. Часть 4) |

## 3. Персоны

| Персона | Контекст | Основная потребность |
|---|---|---|
| **Аллокатор** (основная) | 5–20 активов в 2–4 кошельках на нескольких сетях. Есть целевая пропорция («40% BTC, 30% ETH, 20% стейблы, 10% альты»). Периодически ребалансирует | Видеть текущую аллокацию против целевой в одном месте; знать, что и на сколько купить/продать |
| **DeFi-оператор** (вторичная) | Тот же человек, глубже: заносит залог в Aave, занимает стейблы, размещает их в GMX GM-пулы и Uniswap LP | Видеть гросс-активы, долг и net worth; следить за health factor; помнить, куда размещены заемные средства |

Это один и тот же человек на двух глубинах вовлеченности — поэтому один продукт с фазовым углублением, а не два.

## 4. Основные пользовательские сценарии

1. **Настройка портфеля:** регистрация → добавление адресов кошельков → балансы подтянулись автоматически → задание целевой аллокации → просмотр «текущее vs целевое».
2. **Ежедневная проверка (главный цикл):** открыть дашборд → увидеть стоимость портфеля, отклонения аллокации, P/L к средней цене → уложиться в 30 секунд. Весь UX оптимизируется под этот цикл.
3. **Запись сделки:** купил 0.1 BTC по $95k → внес вручную → средняя цена и unrealized P/L обновились.
4. **Ретроспектива:** открыть историю → графики net worth и аллокации по снепшотам.
5. **Управление левереджем:** увидеть supplied/borrowed в Aave, health factor, и в какие позиции размещены заемные средства.

## 6. Нефункциональные требования

### 6.1. UX и производительность
- **Mobile-first** адаптивная верстка; сценарий «30-секундная проверка» полностью удобен с телефона. Нативных приложений нет.
- Первый содержательный рендер дашборда < 2 с на кэшированных ценах. Везде stale-while-revalidate: мгновенно показываются последние известные данные с меткой свежести; экран «только спиннер» запрещен.
- Минимальная навигация: Дашборд / Сделки / История / Кошельки / Настройки. Никаких «дашбордов из дашбордов».

### 6.2. Надежность и деградация
- Отказ одного апстрима (RPC одной сети, CoinGecko) деградирует только свою секцию с бейджем «данные устарели»; дашборд никогда не падает целиком.
- Ежедневный снепшот-джоб идемпотентен и ретраится; пропущенные снепшоты видны в истории, а не молча отсутствуют.

### 6.3. Безопасность
- **Абсолютное правило: никаких приватных ключей, сид-фраз и подписи транзакций — никогда.** Ни одно поле ввода в продукте не принимает сид-фразу. Это входит в definition of done каждой истории про кошельки. Приложение только читает публичные адреса.
- Auth: email + пароль (argon2id), верификация email, rate-limit на вход, secure-сессии (HttpOnly, SameSite), только HTTPS. TOTP 2FA — Фаза 6.
- **Строгая изоляция данных между аккаунтами на уровне БД** (Row Level Security в Postgres, каждый запрос скоупится по идентификатору пользователя), покрыта автотестами — не только на уровне UI/API.
- Шифрование БД at rest; секреты — в секрет-менеджере хостинга, никогда в коде.
- Приватность: адрес кошелька — чувствительные данные (деанонимизирует состояние). Никакая аналитика/трекеры не получают адреса и балансы.
- Рекомендации по ребалансировке везде подписаны как расчеты, а не финансовые советы.

### 6.4. Бюджет API и лимиты
- Единый **общий серверный кэш цен** для всех пользователей: бэкенд батчами запрашивает цены по объединению активов всех пользователей, TTL 5 минут. Браузер никогда не ходит в CoinGecko напрямую.
- RPC — бесплатный тир одного провайдера (Alchemy) с multicall-батчингом и fallback-транспортами; обновление по запросу + фоновое не чаще раза в 15 минут; backoff при 429.
- Счетчики вызовов каждого внешнего API с первого дня; алерт при 70% лимита тарифа.
- Атрибуция CoinGecko («Price data by CoinGecko» со ссылкой) — обязательна на бесплатном тарифе.

### 6.5. Переносимость данных
- CSV-экспорт активов, сделок и снепшотов — не позднее Фазы 6 (экспорт сделок желательно вместе с Фазой 2: данные о средней цене труднее всего восстановить).
- Все, что пользователь ввел вручную, должно быть экспортируемо. Lock-in отсутствует by design.

## 7. Постоянные non-goals

- Разбор истории транзакций для автоматического вычисления средней цены.
- Подпись/отправка транзакций (repay, supply и т.п.) — приложение никогда ничего не подписывает.
- Налоговая отчетность, FIFO/LIFO-лоты (схема данных допускает FIFO в будущем, но это вне текущего roadmap).
- NFT, не-EVM сети, фиатные валюты кроме USD.

## 8. Критерий успеха MVP

Пользователь проходит путь «регистрация → добавил адреса → видит отклонение аллокации» менее чем за 10 минут и возвращается в приложение минимум раз в неделю.
