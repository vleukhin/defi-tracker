# DeFi Portfolio — дизайн-код 1.0

**Статус:** действующая дизайн-система. Заменяет «Terminal Blue»
([05-dizain-sistema.md](05-dizain-sistema.md)) — тот документ оставлен как
история решений и на текущий интерфейс больше не распространяется.

Правила для всех страниц трекера DeFi-портфеля.

Где это живёт в коде:

| Что | Где |
|---|---|
| Токены обеих тем, `@theme`-маппинг, типографические роли (`.t-*`) | [`src/app/globals.css`](../src/app/globals.css) |
| Примитивы: карточка, метрики, чипы, полосы, таблица, сегменты, «?» | [`src/components/dc/`](../src/components/dc/) |
| Правила записи чисел (`dcUsd`, `dcPp`, `dcTokens`, `dcDelta`) | [`src/lib/format.ts`](../src/lib/format.ts) |
| Шрифты IBM Plex Sans / Mono | [`src/app/layout.tsx`](../src/app/layout.tsx) |

Исходный хендофф (прототипы `.dc.html`, бренд-бук, `tokens.css`) в репозиторий
не переносился — он у владельца продукта.

## 1. Принципы

1. **Число — главный герой.** В каждом блоке одно число крупнее остальных. Три числа одного размера = иерархии нет.
2. **Цвет = смысл.** Зелёный/красный — только прибыль и убыток. Синий — только интерактив. Зоны и активы — свои «данные»-оттенки, среди них нет ни зелёного, ни красного.
3. **Объяснения прячутся.** Методики расчёта — в тултип под «?». В интерфейсе остаётся максимум одна строка-вывод внизу карточки.
4. **Плотность через линии.** Группы данных разделяет волосяная линия 1px и смена фона, а не большой отступ.

## 2. Цвет: четыре роли

| Роль | Где применяется | Токены |
|---|---|---|
| Поверхности | canvas → sunken → surface → raised | `--bg-*` |
| Текст | 4 уровня, ниже третьего только разделители | `--text-1…4` |
| Интерактив | ссылки, primary-кнопка, фокус | `--accent`, `--focus-ring` |
| Данные | зоны, активы, свои/заёмные | `--zone-*`, `--asset-*`, `--money-*` |

Отдельно — семантика: `--profit`, `--loss`, `--warn`. Она **никогда** не используется как фон блока или обводка карточки; только цвет числа, цвет чипа-статуса (заливка 8%, обводка 18%) и маркер на полосе риска.

Запрещено: красить всю строку таблицы из-за отрицательного P/L; цветные градиентные фоны; цветная обводка карточки шире 2px (допустим только верхний бордер 2px как метка зоны).

## 3. Типографика

- **IBM Plex Sans** — весь интерфейс. Всегда `font-variant-numeric: tabular-nums`.
- **IBM Plex Mono** — только денежные суммы от 24px и точные количества токенов. Проценты, ставки, мелкие числа и любые подписи — Sans.
- Шкала и трекинг — в `tokens.css` (`--type-*`). Заголовки с отрицательным letter-spacing, подписи (`--type-label`) — капслок с `+.1em`.
- Минимальные размеры: значение метрики 19px, body 14px, мета 12,5px, подпись 10,5px. Ниже 10,5px не опускаемся.

## 4. Числа и деньги

- Разделитель разрядов — пробел: `$186 495`. Десятичный — запятая: `4,90%`.
- Копейки показываем только до $1000: `$302,91`, но `$25 251`.
- Минус — символ `−` (U+2212), не дефис. Дельта пишется `−$2 847 · −6,2%` (точка-разделитель, без скобок).
- Ставки — два знака (`4,90%`), разница ставок и отклонение от цели — со знаком (`+1,38%`), количества токенов — 4 знака (`6,9777 WETH`).

  > **Отступление от исходного дизайн-кода.** В хендоффе разница ставок
  > записывалась в процентных пунктах — `+1,38 п.п.` По решению владельца
  > продукта единица во всём интерфейсе пишется символом процента.
  > Величина при этом осталась прежней: `+3,02%` рядом с долей `53,02%`
  > означает «на 3,02 пункта выше цели», а не «на 3,02% больше».
  > В коде это `dcPp` / `formatPp` в [`src/lib/format.ts`](../src/lib/format.ts).
- Пустое значение в таблице — `—`, не `$0,00`.
- В таблицах числа выровнены по правому краю, шапка — `--type-label`.

## 5. Компоненты

**Карточка позиции** — четыре полосы сверху вниз:

1. Шапка: плитка протокола 34px (моно-аббревиатура), название h3, чип зоны, мета-строка, статус справа, кнопка меню 30px.
2. Метрики: 2–4 равные ячейки в grid, разделены линией 1px. Ячейка = подпись → значение → дельта, ровно три уровня.
3. Визуалы: на фоне `--bg-sunken`. Полосы данных высотой 7px, радиус 4px, зазор 2px.
4. Вывод: одна строка 12,5px `--text-2` — что это значит для стратегии.

Типы позиций отличаются только наполнением: **LP** — состав + диапазон цены; **депозит** — ставка + спред к займу; **займ** — LTV + запас прочности по HF.

**Кнопки** (высота 34, радиус 8): primary — `--accent`, одна на экран, только создающее действие; secondary — `--bg-raised`; ghost — обводка `--line-strong`; danger — текст `--loss`, фон появляется на hover.

**Поля**: фон `--bg-sunken`, обводка `--line-card`, в фокусе `--accent` + ring 3px `--focus-ring`. Плейсхолдер — `--text-4`.

**Тултип**: фон `--bg-raised`, обводка `--line-strong`, радиус 9px, 12,5px, максимум 300px ширины, одно предложение. Триггер — круг 14px с «?» и обводкой `--line-strong`, `cursor: help`.

**Чипы**: зона — заливка 10% цвета зоны + текст `--zone-*-text`; статус — заливка 8% + обводка 18% + текст семантики; нейтральный — `--bg-chip` + `--text-2`.

**Графики**: линия стоимости портфеля — `--text-1` с заливкой-градиентом 16% → 0; графики количеств — цвет актива (`--asset-*`) с заливкой 22% → 0. Толщина линии 1px (`vector-effect: non-scaling-stroke`), сетка не рисуется, подписи осей — Mono 11,5px `--text-3`. Зелёный/красный в графиках не используются.

Единственное исключение из «сетка не рисуется» — **опорные линии**: ноль на знакопеременном ряде (Прибыль), порог HF и целевой LTV (История риска). Сетка — это повторяющиеся декоративные линии; опорная линия несёт значение, осмысленное независимо от данных: безубыток, порог предупреждения, цель. Правила:

- линия `--line-strong` с подписью `.t-axis`, цвет линейный — зелёного и красного в графике по-прежнему нет;
- **уровни ликвидации** (HF 1,00, ликвидационный LTV) отличаются **формой** — пунктиром, а не цветом: они говорят не «куда стремимся», а «где всё кончится»;
- под опорную линию домен растягивается **только для границы решения** (порог, цель): график риска, на котором не видно границы, отвечает «как менялось», но не «насколько близко». Ликвидационные уровни в домен не входят и рисуются, только если сами в него попали, — иначе кривая расплющится в прямую;
- у графика с опорной линией нет заливки: её основание лежит на нижнем краю домена, а не на линии, и площадь под кривой читалась бы как величина, которой нет.

**Полосы данных**: состав — цвета активов; свои/заёмные — только `--money-own` / `--money-borrowed`; риск — красная и жёлтая зоны в градиенте + маркер «сейчас» 2×15px.

## 6. Сетка и плотность

Контент 1120px по центру, поля страницы 28px, поля карточки 18px, gap сетки 12px, между блоками 16px. Радиусы: карточка 14, вложенный блок 12, контрол 8, чип 7/6. Все отступы кратны 2 (шаг 4 предпочтителен). Шапка приложения 60px, sticky, фон с blur 14px, в правой части — сумма портфеля и дневная дельта.

Брейкпоинты: 1440 / 1280 (сетка метрик 4 → 2 колонки) / 1024 (меню шапки → выдвижная панель справа) / 768 (зоны в столбец) / 375 (карточка позиции: метрики 2 колонки, диапазон на всю ширину). Hit-зона на тач-ширинах — не меньше 44px.

## 7. Тон текста

- Зоны — латиницей (Growth, Yield, Stability), метрики — по-русски.
- Строка-вывод — утверждение, а не инструкция: «по стратегии делать с ней нечего», «заёмные окупаются». Без восклицаний и эмодзи.
- Тултип — формула словами: «Активы минус долг — сколько останется, если закрыть все займы».
- Сноска страницы (уточнение к расчёту) — один раз внизу страницы, 12px, `--text-3`.
- Пустое состояние — «Записей пока нет» + предложенное действие.

## 8. Чек-лист новой страницы

- [ ] h1 + время обновления данных слева, переключатель режима справа.
- [ ] Первый блок отвечает на главный вопрос страницы одним крупным числом.
- [ ] Ни одного абзаца с формулами — всё под «?».
- [ ] Зелёный/красный только на числах P/L и статусах риска.
- [ ] Mono ≥24px для сумм, tabular-nums везде, разряды через пробел, минус — U+2212.
- [ ] Пустые значения — «—»; числа в таблицах вправо.
- [ ] Одна primary-кнопка; формы — в раскрываемом блоке, не в общем потоке.
- [ ] Проверены светлая тема и ширины 1440 / 1280 / 375.

## 9. Что считать нарушением

Новый цвет вне `tokens.css`; Mono в подписях и мелком тексте; больше двух шрифтовых начертаний на экране; абзац-объяснение в интерфейсе; вторая primary-кнопка; заливка карточки цветом зоны; иконки-эмодзи; тень на карточках (тень только у всплывающих слоёв — `--shadow-pop`).
